PHASE 3 — 주문/체결 엔진 구축

목표:
- 주문 생성
- 주문 검증
- 즉시 체결 처리

핵심:
stock-server의 가장 중요한 단계

────────────────────────────────────

3-1. STOCK_ORDER 구축

API:
POST /orders
GET /orders
GET /orders/{id}
POST /orders/{id}/cancel

────────────────────────────────────

3-2. 주문 흐름 구현

1. PIN 인증 완료
2. 계좌 조회
3. 주문 검증
4. 주문 생성
5. 체결 엔진 호출

────────────────────────────────────

3-3. 주문 검증 구현

[ 매수 ]

예수금 >= 주문금액

────────────────────────────────────

[ 매도 ]

보유수량 >= 매도수량

────────────────────────────────────

3-4. 주문 상태 구현

초기:
- REQUESTED
- FILLED
- FAILED

이후 확장:
- PARTIAL_FILLED
- CANCELLED

────────────────────────────────────

3-5. STOCK_EXECUTION 구축

목표:
주문 체결 저장

구조:
ORDER 1:N EXECUTION

────────────────────────────────────

3-6. 체결 엔진 구현

초기 전략:
즉시 체결

흐름:

주문 생성
→ 현재가 조회
→ execution 생성
→ order 상태 변경

────────────────────────────────────

3-7. MARKET 주문 구현

현재가 즉시 체결

────────────────────────────────────

3-8. LIMIT 주문 구현

조건:
현재가 <= 지정가
