PHASE 2 — 시세 시스템 구축

목표:
- 현재가 조회
- 차트 조회
- 더미 시세 생성

전략:
현재는 REST 기반 시세 조회 구현
→ 이후 WebSocket 실시간 확장 예정

────────────────────────────────────

2-1. STOCK_PRICE_HISTORY 구축

기능:
- 현재가 저장
- 시세 이력 저장

────────────────────────────────────

2-2. 더미 시세 Generator 구현

전략:
5초마다 랜덤 가격 변동

예:
73,500
→ 73,700
→ 73,400

────────────────────────────────────

2-3. Scheduler 구현

예:
StockPriceScheduler

역할:
- 시세 생성
- DB 저장

────────────────────────────────────

2-4. 현재가 API 구현

API:
GET /stocks/{stockCode}/price

조회 방식:
최신 row 조회

────────────────────────────────────

2-5. 차트 API 구현

API:
GET /stocks/{stockCode}/chart

조회 방식:
최근 N개 조회

────────────────────────────────────

2-6. WebSocket 확장 고려 구조 추가

현재 구현 X

하지만 구조 준비:

external/
└─ kis/
└─ websocket/

예:
- KisWebSocketClient
- KisRealtimeParser

────────────────────────────────────

2-7. 실시간 확장 고려 포인트

현재:
REST 응답 구조 기반

WebSocket 응답 parser 추가

예:

005930^093015^80500^2^1200

→ parser
→ 내부 Domain 변환
